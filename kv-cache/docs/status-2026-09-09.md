## 2. The big finding: the BetterBench run is INVALID (polluted)
- The full BetterBench run (all 3 phases) produced numbers, but they are **polluted by prefix-cache hits** and cannot be used.
- **Root cause:** vLLM radiance matches the prefix cache by block *content* (not chained prefix). BetterBench's "cold (nonce)" design only varies **block 0**.
- **Evidence:**
  - 2.15M GPU prefix-cache hits + 2.45M external (offload) hits during the run.
  - A/B test at 32k: repeating `_PARA×n` body = **9.1s (3,520 t/s)** vs unique non-repeating = **20.6s (1,555 t/s)** → the repeating body self-caches *within a single request* (2.3× prefill; decode/concurrency reuse the same handful of prompts).
  - `prompt_tokens_total` climbed ~1.85M while ~4.7M tokens were sent; the ~2.45M gap = tokens the offload tier served instead of recomputing.
- **Scope:** the entire run (prefill + decode + concurrency, all 3 levels). No flush endpoint (404 on both raw 5804 and llama-swap 1234).
- **User decision:** "just confirm the diagnosis" — **no re-run performed** yet.
- **Reframe the user landed on:** the pollution is actually a *good result for the tier* — the tier served ~2.45M tokens from RAM/disk ≈ **~26 min of prefill avoided** at the honest cold rate (~1,555 t/s). Internally consistent.

## 3. Why the cache matched *past* the nonce (mechanism)
- It happens specifically in the **Mamba (Gated DeltaNet) layers** — *not* the full-attention KV (which is genuinely prefix-dependent and correct).
- The stride-8 store: keep only when `(abs_chunk_idx + 1) % 8 == 0`; lookup rounds to `N×tokens_per_chunk`. So the served state is `S_boundary` (up to 8 chunks coarser than the exact position), **not** the exact per-position state. The 7-of-8 intermediate states are discarded (never read by lookup).
- This is **inherently approximate by the stride design** — the quantized state is less sensitive to the nonce.
- For strict technical correctness it *shouldn't* happen (KV is prefix-dependent, not content-local).
- The **Gated DeltaNet gate** (finite effective memory) is what makes the stride quantization a *good* approximation in practice.
- **NIAH impact:** modest increase in failure rate; scales with Mamba:full-attention reliance ratio and haystack length. Full-attention is a precise, stride-unaffected fallback; effect larger for shorter haystacks and Mamba-heavy models.

## 4. DASC / DAMP research (the "why this is a real thing" + mitigations)
- **DASC** — arXiv **2608.30386** (Meituan, submitted 31 Aug 2026): *Decay-Aware State Compression for Hybrid Linear-Attention Serving.*
  - Authors: Yanqi Yu, Pingwei Sun, Jianchao Tan, Tao Zhang, Yuchen Xie, Xunliang Cai, Yao Liu (Meituan; Ziqian Zeng SCUT).
  - Two mitigations:
    1. **Retention-horizon unit selection** — omit short-horizon / fast-forgetting units, keep long-horizon / persistent ones (derived from model weights, per-head / per-channel).
    2. **Suffix refresh** — on reuse, refresh the omitted units from a bounded suffix (replay recent tokens).
  - Headline numbers: **2.63× compression, 42.6% lower TTFT, 68.4% higher input throughput.**
  - **Run with unquantized BF16 weights + FP32/BF16 recurrent states** (i.e. NOT our config — see §5).
  - "Implemented in SGLang."
- **DAMP** — arXiv **2608.27513** (same Meituan group, same SGLang implementation): *Decay-Aware Mixed-Precision Recurrent-State Quantization* — this is the **state-precision** (quantization) side, the closer match to our FP8 state/KV.

## 8. Reframed bar (2026-09-09)
- **Contributor is not an AI researcher or a software developer.** The bar is a **best-effort reimplementation + clearly-stated limitations**, not a research-grade DASC reproduction. The artifact must be a **working, measured baseline** with an **explicit, single, well-described gap** to DASC's full method — something others can pick up and extend.

### The shippable best-effort (feasible for a non-researcher)
1. **Two-tier offload (RAM + disk)** for KV + linear-attention state — already built & measured (tier earns its keep: ~2.45M tokens served ≈ ~26 min prefill avoided).
2. **Stride-N=8 state coarsening** ("don't store the exact state at every boundary") — already applied.
3. **Suffix refresh** via ReplaySSM (replay last L tokens on reuse) — exists in a kernel; wire in.

### The one thing we skip (the clearly-labeled gap to DASC)
- DASC's headline win (2.63× / 42.6% / 68.4%) comes from **weight-derived, per-unit retention-horizon selection** (decay-aware, per-head/per-channel omission) — the research-core. **We do not do it.** We approximate with a **uniform** coarsening (the stride) instead.

### The limitations we state up front (so it is not mistaken for a DASC benchmark)
1. Uniform coarsening, not decay-aware per-unit selection → our compression / TTFT numbers are **not comparable** to DASC's 2.63×/42.6%/68.4%.
2. We run **quantized** (MXFP4 weights, FP8 KV); DASC is **unquantized BF16** → deltas not directly transferable.
3. Single model (Qwen3.8-27b) on single HW (AMD R9700), not DASC's test set (Qwen3-Next 80B) or benchmark mix.
4. Suffix window L likely not tuned to DASC's.

### Why others can run with it
- It is a working, measured baseline (offload + stride + suffix refresh) + a *single, named* gap ("add the retention-horizon extraction from the gate weights, per the DASC method") + limitations stated up top. A credible hand-off, not a paper.
